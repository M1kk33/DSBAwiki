# DSBA Wiki

Независимая учебная wiki DSBA. Рабочее приложение с каталогом дисциплин, библиотекой, серверным поиском, административным редактором и постоянным хранением файлов. Интерфейс на русском и английском; названия дисциплин и учебные материалы сохранены на языке источника.

## Язык интерфейса

Кнопка **EN / RU** в шапке переключает язык сайта, включая редактор, фильтры, метаданные страниц и сообщения об ошибках. В диалогах редактора есть такой же переключатель. Русский используется по умолчанию; выбор хранится в cookie `dsba-wiki-locale` на год и применяется при серверном рендеринге. Смена языка обновляет серверные страницы через `router.refresh()`, сохраняя состояние клиентских форм и фильтров. Тема оформления хранится отдельно.

Переводы находятся в `lib/locales/en.json`: ключ — исходный русский текст, значение — английский перевод. `t("Текст")` переводит подпись, а шаблон ``t`Модули ${modules}``` использует ключ `Модули {0}`. Клиентские компоненты получают `t` через `useI18n()`, серверные — через `getServerI18n()`. Названия, описания и содержимое пользовательских материалов передавать в `t` не нужно. Нативный выбор файла, сообщения браузерной валидации и PDF-просмотрщик используют настройки языка браузера.

## Быстрый запуск

Нужен Node.js 22.13+ (проверено на 24.18). Выполняйте команды в папке `wiki`:

```sh
npm ci
npm run setup:local
npm run dev
```

Откройте адрес, показанный сервером, обычно http://localhost:5173. `setup:local` применяет миграции и при отсутствии `.env` создаёт случайный одноразовый ключ администратора. Повторный запуск не очищает базу и не меняет существующий ключ. Нельзя удалять `.wrangler/state`: здесь находятся локальные D1 и R2.

В Windows, если системный npm shim сообщает об отсутствующем `npm-cli.js`, вызовите npm напрямую через установленный Node.js:

```powershell
node 'C:/Program Files/nodejs/node_modules/npm/bin/npm-cli.js' ci
node scripts/setup-local.mjs
node scripts/run-framework.mjs dev
```

## Вход администратора

1. Откройте `/admin` и нажмите «Войти через ChatGPT».
2. В локальной разработке используется тестовый аккаунт `seedy@sites.test`. Имитация входа действует только на loopback и отсутствует в production-сборке.
3. Если администратор ещё не назначен, скопируйте значение `ADMIN_BOOTSTRAP_KEY` из локального `.env` в поле активации.
4. После активации роль хранится в таблице `editors` и привязана к стабильному идентификатору аккаунта. Другой вошедший пользователь не получает доступ к редактору. Ключ больше не назначает новых администраторов.

`.env`, `.wrangler`, временные артефакты и секреты исключены из Git. Никогда не добавляйте ключи в переменные с префиксом `NEXT_PUBLIC_` и не отправляйте `.env` в репозиторий.

На опубликованном сайте вход обрабатывает Sites. Production-база отдельная: локальная активация и локальные материалы не переносятся автоматически. Для первичной настройки production нужен серверный секрет `ADMIN_BOOTSTRAP_KEY`, затем такая же активация нужного аккаунта. После активации секрет можно удалить при следующем развёртывании; существующий администратор сохранится.

## Работа с материалами

- В разделе «Курсы» администратор добавляет и редактирует дисциплины, учебный год, год обучения, модули, группу, описание и источник.
- «Добавить материал» поддерживает файл, Markdown и внешнюю ссылку. При выборе нескольких файлов каждый становится отдельной записью с общими метаданными; название берётся из имени файла.
- Поддерживаются PDF, DOCX, PPTX, XLSX, TXT, MD, CSV и IPYNB, до **16 МиБ** на файл. Устаревшие бинарные DOC/PPT нужно предварительно преобразовать в DOCX/PPTX.
- Укажите курс, тему, модули, тип материала, описание и автора/источник. Если модули не заданы, материал наследует период курса.
- Новые записи по умолчанию — **черновики**. Для публикации требуются атрибуция и подтверждение права размещения. Публикация — осознанное действие администратора.
- Для обновления документа откройте материал, выберите новый файл и сохраните. URL страницы `/resources/:id` и скачивания `/api/files/:id` сохраняется; версия увеличивается.
- Статус «Архив» убирает материал из публичных списков, поиска и скачивания. Его можно восстановить. Необратимого удаления из интерфейса нет.
- PDF открывается во встроенном просмотрщике браузера, если он доступен. Кнопка скачивания работает независимо от предпросмотра. Office-файлы скачиваются для открытия в соответствующем приложении.

## Архитектура

- **React 19 + TypeScript + Vinext/Vite**: маршруты в стиле Next.js App Router и Worker-сборка. Vinext пока имеет статус beta — версии закреплены lockfile, обновления следует проверять перед production.
- **Cloudflare D1 (SQLite)**: дисциплины, метаданные ресурсов, роли и маркер импорта. Запросы параметризованы; изменения схемы через Drizzle migrations.
- **Cloudflare R2**: байты файлов. Ключи объектов генерирует сервер; исходные имена файлов не используются как пути хранения.
- **Sites / ChatGPT sign-in**: production-идентификация. Проверка роли и Origin выполняется сервером при каждой записи. Закрытые материалы защищены также при прямом скачивании.
- **Zod + fflate**: валидация метаданных, ограничение объёма запроса, проверка структуры Office ZIP без извлечения на диск. PDF проверяется по сигнатуре и завершающему маркеру; антивирусной проверки нет.
- **Radix/shadcn**: доступные диалоги, вкладки, списки, выбор значений и адаптивная навигация. Оригинальная иллюстрация панды хранится локально.

Полные тексты не передаются вместе со списками. Библиотека и админка используют серверную фильтрацию и пагинацию. Проверка версии ресурса и даты изменения курса защищает от перезаписи устаревшей формой. Замена файла сначала создаёт новый объект, затем переключает запись в БД и удаляет старый. Если запись в БД не удалась, новый объект удаляется.

```text
app/                страницы и серверные API
components/         интерфейс wiki и редактор
lib/                модель, запросы, валидация
content/            исходные метаданные DSBA
db/schema.ts        декларация таблиц
drizzle/            версионируемые SQL-миграции
scripts/            запуск, локальная настройка и сборка
tests/              интеграционные проверки D1/R2/API
public/             иллюстрация, favicon
.openai/hosting.json идентификатор Sites и логические DB/BUCKET bindings
```

## Проверки

При запущенном dev-сервере:

```sh
npm run typecheck
npm run test:integration
npm run build
```

Интеграционные тесты запускаются только против localhost; создают свой временный курс, проверяют импорт, доступ, CSRF, поиск, фильтры, пагинацию, черновики, права публикации, реальные загрузки/скачивание, замену, конфликт версии и архивирование, затем удаляют только свои записи и объекты. Они активируют локального тестового администратора при первой настройке. Не направляйте этот набор на production.

`npm start` запускает уже собранный Worker локально через Wrangler; он не имитирует production-вход. Для проверки редактора используйте `npm run dev`.

## Развёртывание и обслуживание

Основной поддерживаемый путь — **Sites**, где доступны D1, R2 и доверенная идентификация. Инструкции по сборке, публикации, миграциям, резервному копированию и восстановлению: [docs/OPERATIONS.md](docs/OPERATIONS.md).

Не публикуйте этот Worker напрямую в интернете без замены механизма идентификации: `oai-authenticated-user-*` можно доверять только за Sites dispatch, который удаляет клиентские подделки и устанавливает проверенные значения. Простой перенос на обычный `workers.dev` не является безопасным полным развёртыванием этого приложения.

## Ограничения первой версии

- Поиск по тексту работает для Markdown, UTF-8 TXT/MD/CSV/IPYNB; индексируются первые 200 000 символов. PDF и Office ищутся по названию, теме, описанию и атрибуции. OCR и извлечение текста PDF/Office не включены.
- Markdown поддерживает безопасный базовый набор: заголовки, списки, ссылки, жирный текст и код. Raw HTML не исполняется; LaTeX и сложные таблицы пока не поддерживаются.
- Один администратор, без публичной регистрации редакторов. Модель `editors` допускает дальнейшее расширение. Публичная отправка материалов и контакт администратора пока не настроены.
- Нет истории старых файлов и восстановления предыдущих версий: замена сохраняет ссылку и номер версии, но старые байты удаляются. Для восстановления нужны резервные копии.
- Текущая доступность 14 внешних страниц не проверялась; данные основаны на предоставленном снимке.
- Светлая и тёмная темы переключаются кнопкой в верхней панели. До первого выбора учитывается тема системы, затем выбор сохраняется в браузере. Доступность проверяется вручную по ключевым сценариям; формальная сертификация WCAG не проводилась.
